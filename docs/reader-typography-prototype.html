什么是 Harness

1,842 字约 7 分钟2026-10-29

1

1.1一个被滥用的词 2

「Harness」原本是马具，引申为「把动力约束成可用功的装置」。在 AI 工程里，这个词在 2025 年下半年开始流行，但用法混乱。常见的三种误读： 3

误读说法为什么错
误读一：Harness = 提示词模板 “我们的 harness 就是那套 system prompt” 提示词是内容，Harness 是承载内容的机器。换一套 prompt 不叫换 harness
误读二：Harness = Agent 框架 “我们用 LangGraph，所以有 harness 了” 框架提供编排原语；Harness 提供已组装好的运行时。LangGraph 是零件箱，Claude Code 是整车
误读三：Harness = 模型外壳 “就是套在模型外面的壳” “壳”暗示被动。Harness 是主动的：它决定模型看到什么、能做什么、做完算什么
4

一个更准确的说法：

Harness 是把「模型的一次次 token 生成」转换成「一件可交付、可恢复、可审计的工作」的运行时系统。

5

注意这句话里有四个承诺，每一个都是一票否决项：可交付（有终止与验收）、可恢复（崩了能续）、可审计（每步有据可查）、运行时（不是文档，是跑起来的进程）。

1.2五条判据：什么算 Harness

判断一个东西是不是 Harness，用下面五条。五条全中才是，中三条只能叫「Agent 脚手架」。1

判据具体问法反例
C1 自有循环 它自己决定“再想一轮”还是“收工”，还是把控制权交回调用方？ 单次 chat.completions 封装、一次 RAG 问答链
C2 工具执行闭环 工具结果是否回灌进下一轮上下文，并可能改变后续决策？ Function calling 只返回给前端渲染，不进模型
C3 上下文生命周期 有没有预算、裁剪、压缩、卸载、重建？还是把历史无限拼接？ 简单 messages.append() 的聊天机器人
C4 权限与执行边界 有没有“这一步能不能做”的判断，以及做在哪（本机 / 容器 / 远端）？ 直接 exec() 任意命令，无审批无沙箱
C5 状态可恢复 进程被杀后，能否从某个检查点继续，且不重复副作用？ 内存态会话，重启即失忆

用这五条去卡，会得到一个反直觉的结论：很多自称 Agent 的产品其实是“带工具的聊天”（缺 C1/C5），而很多自称“CLI 工具”的其实是完整 Harness（Codex CLI、Claude Code、Gemini CLI 五条全中）。

面试可用的一句话：判断是不是 Harness，不看它有没有“Agent”字样，看它有没有“循环 + 回灌 + 上下文预算 + 执行边界 + 可恢复状态”这五件套。

1.3五个概念的边界

这是最容易混淆的一组。用「谁决定控制流」和「是否已组装」两个轴来切：

                已组装（开箱即用）
                      ▲
                      │
     Claude Code      │      Codex CLI
     Gemini CLI       │      DeepSeek Harness
 ─────────────────────┼───────────────────────►
 库 / 零件            │                  平台 / 服务
 LangGraph            │      AgentCore / Foundry
 LlamaIndex           │      Vertex Agent Engine
                      │
                未组装（需自己搭）6
Q1. 一个只有 function calling、把工具结果返回给前端渲染的系统，缺哪几条判据？

缺 C2（工具结果回灌） 是致命的：结果只给前端渲染，模型看不到自己做了什么，无法基于结果做下一步决策。连带缺 C3、C4、C5，只剩 C1 的一半——有调用，但没闭环。
