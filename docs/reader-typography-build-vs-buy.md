# 阅读面：社区现成方案 vs A+B+C

> 采集时间：2026-11-05。下载量为 npm 上周数据，星标为 GitHub 当前值，只作热度参考，不作质量结论。
> 实测方法：同一篇文章（《什么是 Harness》1.1–1.3），同一 1440px 视口，分别套用社区样式与方案 A，量字号 / 行高 / 行长 / 表元内距。

---

## 0. 结论

1. **没有一个「开箱即用的中文长文阅读器」。** 社区给的是四层零件：排版 CSS、Markdown 能力、交互件、字体工具。把它们拼起来能跑，但拼出来的不是你的产品。
2. **两个最主流的 drop-in 都越过中文排版红线。** GitHub 官方样式实测 16px / 1.50 / **56.3 字每行**；中文排版库 typo.css 实测 16px / 1.75 / **48.0 字每行**。中文舒适区是 30–40 字，WCAG 1.4.8（AAA）的 CJK 上限是 40 字。
3. **该买的是「能力」，不该买的是「观感」。** 解析、锚点、脚注、代码高亮、字体切片 → 买；行高、行长、字体、表格、批注边注 → 自研。
4. **社区拼装并不比 A+B 快。** 接入半天，覆盖冲突 2–3 天，之后每次升级都要回归；总成本与自研接近，但把风险推到了后面。

## 1. 实测：同一篇文章，四种样式

| 方案 | 字体 | 字号 | 行高 | 行长 | 表元内距 | 观感 |
|---|---|---|---|---|---|---|
| Habitat 现状 | Noto Serif SC | 17px | **1.95** | 38.4 字 | **1px** | 正文发虚，表格挤成一团 |
| github-markdown-css 5.9.0 | 系统 sans | 16px | **1.50** | **56.3 字** | 6 / 13px | 一眼 GitHub，行太长，中文偏挤 |
| typo.css（2026 版） | PingFang SC | 16px | 1.75 | **48.0 字** | 8 / 16px | 通用中文博客，青绿引文、网格表 |
| 方案 A（自研） | Noto Sans SC | 17px | 1.78 | 34.0 字 | 11px | 纸墨感，横线制表，层级清楚 |

三点值得注意：

- **github-markdown-css 本身不约束行长。** 56.3 字是我按 GitHub 常见的 980px 容器测的；即便收到 720px 也有 45 字，仍超 40。库把「多宽」交给宿主，而宿主通常按拉丁文习惯给宽度。
- **typo.css 自己推荐的 `.typo-readable { max-width: 48em }`，按 16px 算是 48 字。** 48em 对拉丁文约 70–80 字符，是合理值；对中文直接超限 20%。这不是库的错，是「通用值」在中文场景失效。
- **两家都把表格做对了，也都没做对。** GitHub 的 6/13px 内距 + 全网格，比现状可读，但网格与「少边框、重分层」相冲；typo.css 的浅底表头是 2010 年代后台味。表格必须自己定规则。

### 第 5 层 · 整站框架（不适用）

## 3. 逐项判断：买什么，为什么

### 不买：@tailwindcss/typography

- 热度最高（2495 万/周），确实经过大规模验证。
- 但它是「给裸 HTML 一套还不错的中性排版」，**默认值不是中文的**：`blockquote` 斜体、`code` 加反引号、行高按拉丁文给。
- 要用它就得把 30+ 条规则覆盖成你的纸墨，而覆盖完的产物已经和它没关系了——付费的是它的默认值，退掉的是它的默认值。
- 还要引入 Tailwind 构建链。当前项目是纯 CSS 变量体系（`tokens.css`），为一段 prose 引入框架不划算。

### 不买：github-markdown-css

- 44.8 万/周、9k★，最省事的 drop-in，10 分钟能出效果。
- 实测 1.50 行高 + 无 measure 约束，中文长文会又挤又长。
- 它的价值是**规则参考**：表格的 `border-collapse`、`th` 背景、代码块滚动、任务列表样式，抄规则比引整包划算。

### 借规则不借库：Han.css

- 它是唯一把中文标点挤压、中西混排、行尾悬挂、章节边界都做全的框架，2.5k★。
- 但：最后 tag 是 2015 年，npm 停在 2016；工作方式是**改写 DOM**（把标点包进 `span`），要求样式表先于一切加载；`Han.init()` 会与 React 的 `dangerouslySetInnerHTML`、以及你现有的批注 `<mark>` 注入相互干扰。
- 2026 年的浏览器已经用 `text-spacing-trim` / `text-autospace` 原生覆盖了它 80% 的收益。**把它的规则清单当验收项，不引它的运行时。**

### 买：Shiki

- 3681 万/周、13.9k★、两天前还在发版。
- 现状 `.prose code/pre` 只换了字体（`app.css:1089`），没有高亮。Shiki 的双主题输出能直接吃你的凝脂/玄墨两套 theme。
- 注意：只加载实际用到的语言与主题，别把全量 bundle 带进来。

### 买：markdown-it 的两个插件

- `markdown-it-anchor`（428 万/周）解决 B 的标题 id 与深链，零架构改动。
- `markdown-it-footnote`（103 万/周）解决 C 的脚注。
- 这两个是「加一行配置」的收益，没有理由自研。

### 不买：mark.js / tocbot / reading-time

- `mark.js` 停更 8 年；现有实现（`Reader.tsx:128-140`）用正则替换 HTML 字符串，遇到嵌套标签或跨节点引文会失效甚至破坏 DOM。正确做法是 Range API 包 `<mark>`，约 60 行。
- `tocbot` 为「目录高亮」引入一个库，不如 40 行 IntersectionObserver。
- `reading-time` 按空格分词，中文会算成几十秒。

## 4. 对比矩阵：社区拼装 vs A+B+C

| 维度 | 社区拼装（github-markdown-css + 覆盖） | A+B+C（自研排版 + 买能力） |
|---|---|---|
| 出效果速度 | 半天 | A 半天 / B 3–5 天 |
| 中文正确性 | 需自己补 measure、行高、标点 | 一次定对 |
| 品牌一致性 | 低，最终是「改过的 GitHub」 | 高，就是「档案刊物」 |
| 样式冲突 | 高，30+ 条覆盖，升级即破 | 无外部样式依赖 |
| 后续维护 | 每次升级回归 0.5 天 | 只维护自己的 CSS |
| 可逆性 | 删包即可，但覆盖层已散落 | 整段回滚 |
| 长期成本 | 先省 2 天，后面持续缴税 | 先多 2 天，后面不缴税 |

**估算**：社区拼装 ≈ 0.5 天接入 + 2 天覆盖 + 1 天主题适配 = **3.5 天**；A+B ≈ 0.5–1 + 3–5 = **4–6 天**。差距只有 1–2 天，但一个是「别人的骨架刷你的漆」，一个是「你的骨架」。

## 5. 建议：分层采购

| 层 | 决策 | 具体 |
|---|---|---|
| 排版 CSS | **自研** | A 的 `.prose` 全套；只抄 github-markdown-css 的表格规则、Han.css 的规则清单 |
| Markdown 能力 | **买** | `markdown-it-anchor` + `markdown-it-footnote`（+ 可选 `attrs`） |
| 代码高亮 | **买** | `shiki` + `@shikijs/markdown-it`，限语言限主题 |
| 目录/进度 | **自研** | IntersectionObserver + CSS 变量，约 60 行 |
| 批注高亮 | **自研** | Range API，替换现有正则方案 |
| 字体切片 | **买** | `cn-font-split`，仅在 C 阶段启用 |
| EPUB | **可选买** | `epubjs`，独立排期 |
| 安全 | **买** | `dompurify` 兜底 `html:true` |
| 整站框架 | **不用** | 会替换掉产品外壳，不是排版问题 |

一句话：**影响识别度的自研，不影响识别度的买。** 排版、构图、批注交互决定「这是不是 Habitat」；解析、高亮、切片只是管道。

## 6. 如果仍想用现成库，最低风险的用法

1. 用 `@layer vendor` 包住第三方样式，自己的 `.prose` 放在后面，永远能覆盖。
2. 只取**元素级规则**（table / pre / blockquote），不要它的 `body`、`font-family`、`max-width`。
3. 颜色全部映射到 `--ink/--rule/--accent`，不留硬编码色（typo.css 的 `#1abc9c` 就是典型冲突）。
4. 不引它的 JS 运行时（Han.css 的 DOM 改写、mark.js 的遍历），只借 CSS 思路。
5. 升级前跑一次视觉回归：四档视口 × 三套主题 × 四个代表元素（正文/表格/引文/代码）。

---

## 7. 不推荐清单

- ❌ 把 `github-markdown-css` 直接挂到 `.prose`：观感立刻变成 GitHub，且中文行太长。
- ❌ 引 `@tailwindcss/typography` 再覆盖 30 条：为了默认值付费，再把默认值全部退掉。
- ❌ 全量引 `Han.css`：2015 年的运行时 + DOM 改写，与 React 和现有批注注入冲突。
- ❌ 用 `mark.js` / `markdown-it-task-lists` / `reading-time`：停更或中文不准。
- ❌ 换 VitePress / Mintlify 之类的文档框架：那是换产品，不是改排版。
