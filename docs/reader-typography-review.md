# 阅读面排版评审：现状诊断、业界基准与三套优化方案

> 对象：`src/domains/reading/Reader.tsx` + `src/styles/app.css`（阅读器段）
> 方法：读实现 → 量参数 → 对基准 → 做样张 → 给方案
> 配套样张：`docs/reader-typography-prototype.html`（现状 / A / B / C 四态可切，含实时量尺与朱砂校样标记）

---

## 0. 结论先说

1. **行长不是问题，行高、层级、表格、字体选择才是。** 中档 38.4 字/行，落在中文 30–40 字区间内；真正拉低阅读体验的是「宋体正文 + 1.95 行高 + h3 几乎等于正文 + 表格零样式」这一组叠加。
2. **表格没有任何专属样式**，是截图里最刺眼的一处，也是投入产出比最高的一处：`app.css` 的 `.prose` 段落（1073–1094）里没有一条 `table/th/td` 规则，markdown 表格退化成浏览器默认（单元格内距 1px、无分隔、表头居中）。
3. **设计系统自己和自己打架**：`tokens.css:4` 写「衬线做结构、无衬线做阅读」，`app.css:1075` 却把正文设成 `--font-display`（衬线）。正文与标题同族，层级只能靠字号硬撑，于是 h3 塌了。
4. **两处对比度不达 WCAG AA**：凝脂 `--text-3` 4.39:1、漂青 3.85:1，而它们正用于 11–12px 的进度、目录编号、说明文字。
5. 建议路径：**A（半天）立刻做 → B（3–5 天）下一迭代 → C 只取 3 项，字体工程缓做**。A 单独落地就能把「越界项」从 2 项清到 0。

## 1. 现状实测

### 1.1 度量（本机 16px 根字号、`凝脂` 主题、1440×900 实测）

| 项 | 现状 | 业界基准 | 判定 |
|---|---|---|---|
| 正文字号 | 17px（`--fs-body`） | 桌面 16–19px | 通过 |
| 行长 · 中 | **38.4 字**（652px） | 中文 30–40 字；WCAG 1.4.8 上限 40 字 | 通过，贴上限 |
| 行长 · 宽 | **48.2 字**（820px） | ≤40 字（CJK） | **超限 20%** |
| 行长 · 窄 | 30.6 字（520px） | 30–40 字 | 通过 |
| 行高 | **1.95**（行盒 33.2px） | 桌面中文 1.6–1.8 | 偏松 |
| 段间距 | **0.94em**（16px） | ≥1.1em，且应明显大于行距 | 偏紧 |
| h3 / 正文 | **1.08**（18.4 / 17） | 每级 ≥1.2 | **层级塌陷** |
| h2 / 正文 | 1.36（23.2 / 17） | ≥1.4 | 偏弱 |
| 表元内距 | **1px**（UA 默认） | 8–14px | **缺失** |
| 代码块行高 | 继承 1.95 | 1.5–1.65（等宽需更紧） | 偏松，ASCII 图会散 |

对应代码：`app.css:1073-1082`；宽度档位 `tokens.css:69-71`。

> 一个容易忽略的点：`--reading-w` 的「宽」档 51.25rem = 820px，按 17px 正文算是 48.2 字，**超过 WCAG 1.4.8 对 CJK 的 40 字上限**。要么把宽档收到 40 字（680px），要么把宽档定义为「表格/代码专用宽度」，正文仍锁 40 字内。

### 1.2 对比度（WCAG 2.1，正常字号需 ≥4.5:1）

| 主题 | 用途 | 前景/背景 | 比值 | 判定 |
|---|---|---|---|---|
| 凝脂 | 正文 | `#1e1a15` / `#f1ece1` | 14.69 | 通过（AAA） |
| 凝脂 | 次要文字 | `#5b5346` / `#f1ece1` | 6.43 | 通过 |
| 凝脂 | **元信息** | `#756c5e` / `#f1ece1` | **4.39** | **不达 AA** |
| 漂青 | 正文 | `#131f1c` / `#eaf1ee` | 14.76 | 通过 |
| 漂青 | **元信息** | `#6b7c74` / `#eaf1ee` | **3.85** | **不达 AA** |
| 玄墨 | 元信息 | `#8a8478` / `#121314` | 5.01 | 通过 |

`--text-3` 被用于 `.toc-no`（`app.css:1024`）、`.toc-sub`（1004）、`.toc-foot`（1009）、`.reader-pct`（1045）、`.section-note`（1704）——全是 10.5–12px 的小字，恰好是最需要对比度的地方。

### 1.3 结构（截图与实现逐条对照）

| # | 现象 | 证据 |
|---|---|---|
| 1 | 表格无内距、无分隔、表头与正文同级 | `app.css:1073-1094` 无 `table` 规则；`.table`（558）是给数据页用的类，markdown 产物不带该类 |
| 2 | 正文列贴左，右侧留 200px 死白再接 300px 边栏 | `app.css:1075` 只有 `max-width`，无 `margin-inline:auto`；三栏 `app.css:995` |
| 3 | 进度出现 4 次 | `Reader.tsx:163`、`188`、`200`、右下浮层 |
| 4 | 常驻动作 8 个 | `Reader.tsx:198-221`（章节 + 百分比 + 窄/中/宽 + 标记读完 + 衍生 + 问 + 批注） |
| 5 | 目录只有章级，没有节级锚点 | `Reader.tsx:165-185` 只渲染 `work.parts`；`md.render`（120）未注入 heading id |
| 6 | 阅读位置按百分比恢复，换字号会漂 | `Reader.tsx:49-62` 用 `scrollTop = (scrollHeight-clientHeight)*ratio` |
| 7 | 滚动每帧触发整页重渲染 | `Reader.tsx:66-81` 每次 `setPct` 都重渲 TOC/批注/正文容器 |
| 8 | 中文细节全缺 | 无 `text-spacing-trim` / `text-autospace` / `line-break:strict` / `text-wrap:pretty` |

### 1.4 根源：两套字号阶梯并存

- 令牌层：`--t-h3: 1.0625rem`(17) 与 `--t-body: 0.9375rem`(15) 只差 13%（`tokens.css:22-23`）。
- 正文层：又自定义一套 30.4 / 23.2 / 18.4 / 17（`app.css:1080-1082`）。

结果是「同一个 h3，在卡片里是 17px、在正文里是 18.4px」，而正文本身又是 17px——层级不可预测。**先收敛成一套 1.25 倍率的阶梯，再谈调字号。**

## 2. 业界基准

### 2.1 产品横比

> 数值来自公开文档与截图估读，作方向参考，不作精确规格。

| 产品 | 正文 | 行高 | 行长 | 字体策略 | 表格 | 阅读 chrome |
|---|---|---|---|---|---|---|
| Readwise Reader | 20px（14–80 可调） | 1.4 默认，可调 | medium 档，可调 | 衬线/无衬线/Atkinson 可选 | 简化 | 左右栏可折叠；批注在右侧边注；Aa 面板集中所有排版项 |
| Notion | 16px | 1.5 | 三档页宽 | 系统 sans | 轻网格 | 目录常驻，块级 hover |
| Stripe Docs | 16px | ~1.6 | ~65ch | sans | 横线表 + 代码块标题栏 | 右侧目录 + 锚点高亮 |
| Mintlify / GitBook | 16px | 1.65 | 65ch | sans | 横线表 + sticky 表头 | 右目录、可搜、锚点 |
| Medium | 21px | 1.58 | ~65ch | 衬线 | 图片为主 | 几乎无 chrome |
| Apple Books / Kindle | 可调 | 1.5–1.8 | 可调 | 宋/黑/楷 | — | 页边留白 + 进度 |
| 微信读书 | 17–19px | 1.6–1.8 | 28–35 字 | 宋/黑/楷可换 | — | 批注在页边，进度单一 |
| Obsidian | 16px | 1.6 | 可调 | 主题字体 | 基础 | 大纲 + 反链 |

### 2.2 五条共识

1. **行长有硬上限，但「可调 + 稳定」比「最优值」更重要。** 中文 30–40 字是共识区间（[光明网](https://m.gmw.cn/toutiao/2026-04/17/content_1304422414.htm)、[万智](https://www.wanzhiweb.com/xwzx/jyfx/16981.html)），WCAG 1.4.8 把 CJK 上限定在 40 字。
2. **中文行高 1.6–1.8，超过 1.9 段落会散。** 行距一旦大于段距的 1.5 倍，「行内关系」就弱于「段间关系」，读者会把一段读成若干行（[Script Walker 规格](https://scriptwalker.app/blog/traditional-chinese-web-typography-spec-2026?set_locale=zh)）。
3. **屏幕长文优先无衬线，衬线留给标题与引文。** 宋体横画细，小字号屏显易断笔；这也是 `tokens.css:4` 原本的主张（[字由](https://www.hellofont.cn/article/best-fonts-body-text)、[猫啃](https://www.maoken.com/article-list/free-commercial-fonts-for-body-text-typesetting)）。
4. **表格要当「第二等公民」专门设计。** 横线制表（无竖线）、表头 12px/600/字距 .12em、单元格 10–14px 内距、数字等宽右对齐、窄屏横向滚动 + 边缘渐隐——Stripe / Mintlify / Notion 三家做法高度一致。
5. **chrome 要能被收起来。** 常驻动作 ≤3、进度只出现一次、侧栏可折叠、排版项收进一个 Aa 面板——Readwise Reader 是做得最彻底的。

### 2.3 中文特有的三项（低成本、高感知）

| 能力 | CSS | 现状 | 作用 |
|---|---|---|---|
| 标点挤压 | `text-spacing-trim: trim-start` | 无 | 连续全角标点不再出空洞 |
| 中西混排间距 | `text-autospace: normal` | 无（靠手打空格） | `Harness 是` 自动留 1/8 em |
| 避头尾 / 孤行 | `line-break: strict` + `text-wrap: pretty` | 无 | 标点不落行首，末行不出单字 |

兼容性（截至 2026 年初）：`text-spacing-trim` Chrome/Safari 可用、Firefox 未跟进；`text-autospace` Safari 18.4 起。**用 `@supports` 渐进增强，退化后仍是可读的普通排版。**

## 3. 三套方案

### 方案 A · 校准（Calibration）

**范围**：只动正文与 markdown 元素样式，不动布局结构。半天，纯 CSS + 1 个 `margin-inline:auto`。

| 改动 | 从 | 到 |
|---|---|---|
| 正文字体 | `--font-display`（宋） | `--font-sans`（黑），标题仍宋 |
| 字号 / 行高 | 17 / 1.95 | 17 / **1.78** |
| 段距 | 0.94em | **1.15em** |
| 行长 | 38.4 字（贴上限） | **34 字**（578px），宽档锁 40 字 |
| 正文列 | 贴左 | `margin-inline:auto` 居中 |
| h2 / h3 | 1.36 / 1.08 倍 | **1.5 / 1.2 倍**，h2 上方 2.35em 留白 |
| 表格 | 无样式 | 横线制表：表头 10.5px mono 字距 .12em + 1px 下框；单元格 11px 内距；行间 hairline；末行加重收口；首列 26%；窄屏 `overflow-x:auto` + `min-width:520px` |
| 引文 | 2px 左边线 | 衬线 + 1.04em + 行高 1.8 |
| 代码块 | 继承 1.95 | 12px / 1.62，左侧 2px 轨，无圆角 |
| 分隔线 | 灰线 | 朱砂 `※` |
| CJK | 无 | `text-spacing-trim` + `text-autospace` + `text-wrap:pretty` |
| 对比度 | 4.39 / 3.85 | 凝脂 `#6b6252`、漂青 `#5f7068`，均 ≥4.5 |

**落点**：`app.css:1073-1094` 整段替换；`tokens.css:96,130` 两个色值。
**成本**：0.5–1 人日。**风险**：极低，纯样式，可整段回滚。
**样张实测**：越界项 2 → 0；行长 34.0 字；行高 1.78；表元内距 11px。

---

### 方案 B · 重构（Reading Mode）

**范围**：A 全部 + 阅读器结构。3–5 人日。

1. **阅读条瘦身**：常驻只留「章节名 / Aa / ⋯ / 批注」，窄中宽与标记读完收进 Aa 面板（`Reader.tsx:198-221`）。
2. **进度只留一处**：删掉 `toc-sub`、`toc-foot` 与浮层里的百分比，只保留阅读条下沿 2px 进度线。
3. **目录两级**：`md.render` 前注入 heading id（markdown-it 的 `anchor` 能力或渲染后遍历），左侧展开当前章的 1.1–1.8，滚动高亮当前节（IntersectionObserver）。
4. **边注取代卡片栏**：批注从右栏卡片改为正文外侧边注，与段落基线对齐，hover 联动原文高亮；空态收成一行（`Reader.tsx:262-299`）。
5. **章扉页**：章号 + 标题 + 字数/时长 + 来源，给每章一个「翻页」的动作感。
6. **位置恢复改锚点**：存 `{headingId, offsetRatio}`，换字号/窗口不漂（`Reader.tsx:49-62`）。
7. **专注模式**：`F` 收起两侧 + 工具栏，正文居中，浮层 AI 药丸隐藏（截图右下那颗）。
8. **滚动性能**：进度写入 CSS 变量或独立组件，避免整页重渲染（`Reader.tsx:66-81`）。

**成本**：3–5 人日。**风险**：中，涉及组件结构调整，需要 E2E 回归（`reader-body`、`reader-main`、`toc-item` 等 testid 保持）。
**样张实测**：B 态单条工具栏 3 个动作、1 处进度、目录 3 级、边注 3 条与标题对齐。

---

### 方案 C · 纸刊（Typeset）

**范围**：B 全部 + 印刷级能力。1.5–2 周，其中一半在字体工程。

| 能力 | 说明 | 成本 |
|---|---|---|
| 阅读字体三选 | 宋（Noto Serif SC）/ 黑（Noto Sans SC）/ 楷（霞鹜文楷），`size-adjust` 防切换跳动 | 字体子集化 + CDN，2–4 天 |
| 段首缩进模式 | 中文书籍惯例：`text-indent:2em` + 段距降到 0.2em；与「段距模式」二选一 | 0.5 天 |
| 脚注 / 参考文献 | markdown-it-footnote + 文末注 + 上标跳转 | 1 天 |
| 刊物表格 | 双线表头、数字列右对齐、跨页表头、表注 | 1 天 |
| 打印 / PDF | 扩展现有 `@media print`（`app.css:2149-2153`），页码、页眉、脚注区 | 1–2 天 |

**风险**：中文字体单字重 3–8MB，不做子集化会拖垮首屏；`text-spacing-trim` 在 Firefox 无效果，必须验证退化态。
**建议**：C 里只取「CJK 三项 + 脚注 + 打印」，**字体工程单独排期**，不要和阅读面改造绑在一起。

## 4. 对比与推荐

| 维度 | A 校准 | B 重构 | C 纸刊 |
|---|---|---|---|
| 阅读体验提升 | ★★★☆ | ★★★★★ | ★★★★★ |
| 投入 | 0.5–1 天 | 3–5 天 | 1.5–2 周 |
| 风险 | 极低 | 中 | 中高（字体） |
| 可逆性 | 整段 CSS 回滚 | 组件级回滚 | 字体缓存需清理 |
| 对现有设计语言 | 完全保留 | 保留并强化 | 完全保留 |
| 建议 | **立即** | **下一迭代** | **择项，缓做** |

**推荐路径**：先落 A（半天就能看到截图里那张表变干净、正文不再发虚），把 B 排进下一个迭代，C 只做三项低成本项。

> 社区现成方案（Tailwind Typography / github-markdown-css / typo.css / Han.css）与本方案的逐项对比、实测数据与「买 / 自研」分层建议，见 [`reader-typography-build-vs-buy.md`](reader-typography-build-vs-buy.md)。

## 6. 落地记录（2026-11-05）

按「A 全套 + B 全套 + C 的三项低成本项」实现；C 的字体子集化仍留作独立排期。

| 层 | 落地内容 | 落点 |
|---|---|---|
| 令牌 | `--text-3` 对比度修正（凝脂 4.39→5.10、漂青 3.85→4.98）；行宽改为 `字号 × 30/34/40`；新增 `--reader-size` / `--reader-body-font` | `src/styles/tokens.css` |
| 正文 | 黑体 17 / 1.78；h2 1.5em、h3 1.2em；段距 1.15em；横线表格 + 首列 26% + 窄屏滚动；引文衬线；代码 12/1.62 + 语言角标；`※` 分隔；脚注；`text-spacing-trim` / `text-autospace` / `line-break:strict` / `text-wrap:pretty`；段首缩进开关；打印规则 | `src/styles/app.css` |
| 结构 | 单条工具栏（读完 / 衍生 / Aa / 问 / 批注 / 专注）；两级目录 + 滚动高亮；边注（≥1320）与文末批注（<1320）；进度只留阅读条下沿；章扉页（章号 / 标题 / 字数 / 时长）；位置按标题锚点存取 | `src/domains/reading/Reader.tsx` |

| 偏好 | `readerSize` / `readerFont` / `readerIndent` 持久化到 `<html>` | `src/app/ui.ts` |

**实测**（1440×900，凝脂，Harness 第 1 章）：

- 正文 17px / 1.78 / 34.0 字；「宽」档 40 字（等于 CJK 上限）；「窄」档 30 字
- 表元内距 10px，表头 10.5px mono，`<table>` 自动包 `.table-scroll`
- 3 条批注全部落在文本节点上（`mark` 内无 `<p>`），边注与引文同高（误差 0）

- 三套主题正文对比度 ≥14.7:1，元信息 ≥4.98:1
